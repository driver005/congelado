# Documentation [¶](https://rfl.getml.com/docs-readme/\#documentation)

## The basics [¶](https://rfl.getml.com/docs-readme/\#the-basics)

[Structs](https://rfl.getml.com/concepts/structs/) \- Recaps the motivating example in the README. A struct is the equivalent of an AND statement or a product type in type theory.

[Optional fields](https://rfl.getml.com/optional_fields/) \- For defining fields in your serialized format that might be absent in some cases.

[Struct flattening](https://rfl.getml.com/flatten_structs/) \- For making struct A "inherit" the fields of struct B.

[Processors](https://rfl.getml.com/concepts/processors/) \- For modifying the structs before serialization and deserialization. For instance, processors can be used to transform all field names from `snake_case` to `camelCase`.

[The rfl::Field-syntax](https://rfl.getml.com/concepts/field_syntax/) \- Describes an alternative syntax which requires slightly more effort, but allows for some powerful functionalities.

[String literals](https://rfl.getml.com/literals/) \- For representing strings that can only assume a limited number of enumerated values.

[Enums](https://rfl.getml.com/enums/) \- Describes how reflect-cpp handles C++ enums.

[std::variant and rfl::TaggedUnion](https://rfl.getml.com/variants_and_tagged_unions/) \- For structs that can be one of several formats. This is the equivalent of an OR statement or a sum type in type theory.

[rfl::Box and rfl::Ref](https://rfl.getml.com/rfl_ref/) \- For defining recursive structures.

[rfl::Timestamp and std::chrono::duration](https://rfl.getml.com/timestamps/) \- For serializing and deserializing timestamps and durations.

[rfl::Skip](https://rfl.getml.com/rfl_skip/) \- For skipping fields during serialization and/or deserialization.

[rfl::Commented](https://rfl.getml.com/commented/) \- For adding comments to your serialized format (only supported by some formats, such as YAML or XML).

[rfl::Result](https://rfl.getml.com/result/) \- For error handling without exceptions.

[Standard containers](https://rfl.getml.com/standard_containers/) \- Describes how reflect-cpp treats containers in the standard library.

[C arrays and inheritance](https://rfl.getml.com/c_arrays_and_inheritance/) \- Describes how reflect-cpp handles C arrays and inheritance.

[rfl::Bytestring](https://rfl.getml.com/bytestring/) \- Describes how reflect-cpp handles binary strings for formats that support them.

[rfl::Binary, rfl::Hex and rfl::Oct](https://rfl.getml.com/number_systems/)\- For expressing numbers in different formats.

[Default values](https://rfl.getml.com/default_val/) \- For defining default values for fields that might be absent during deserialization.

[Atomic types](https://rfl.getml.com/atomic/) \- For serializing and deserializing atomic types.

## Validation [¶](https://rfl.getml.com/docs-readme/\#validation)

[Regex patterns](https://rfl.getml.com/patterns/) \- For requiring that strings follow used-defined regex patterns.

[Validating numbers](https://rfl.getml.com/validating_numbers/) \- For imposing constraints on numbers.

[Composing validators](https://rfl.getml.com/composing_validators/) \- For defining more complex validators using operators such as `rfl::AllOf` or `rfl::AnyOf`.

[Size validation](https://rfl.getml.com/size_validation/) \- For imposing size constraints on containers such as `std::vector` or `std::string`.

[JSON schema](https://rfl.getml.com/json_schema/) \- For validating your schema before you even send it to your C++ backend.

## Generic elements [¶](https://rfl.getml.com/docs-readme/\#generic-elements)

[rfl::Object](https://rfl.getml.com/object/) \- A map-like type representing a object with field names that are unknown at compile time.

[rfl::Generic](https://rfl.getml.com/generic/) \- A catch-all type that can represent (almost) anything.

[rfl::ExtraFields](https://rfl.getml.com/extra_fields/) \- For adding extra fields to your structs, the names of which are unknown at compile time.

## Custom classes [¶](https://rfl.getml.com/docs-readme/\#custom-classes)

[Custom classes](https://rfl.getml.com/concepts/custom_classes/) \- For custom classes with private fields.

[Custom parsers for your classes](https://rfl.getml.com/custom_parser/) \- For custom classes with private fields that you want (or need) to leave absolutely untouched.

## Useful helper functions and classes [¶](https://rfl.getml.com/docs-readme/\#useful-helper-functions-and-classes)

[rfl::replace](https://rfl.getml.com/replace/) \- For replacing one or several fields in a struct.

[rfl::as](https://rfl.getml.com/as/) \- For casting structs as other structs.

[rfl::NamedTuple](https://rfl.getml.com/named_tuple/) \- For structural typing.

[rfl::Tuple](https://rfl.getml.com/rfl_tuple/) \- An alternative to `std::tuple` that compiles more quickly.

[rfl::to\_view](https://rfl.getml.com/to_view/) \- For accessing fields of a struct by index or name.

## Advanced topics [¶](https://rfl.getml.com/docs-readme/\#advanced-topics)

[Supporting your own format](https://rfl.getml.com/supported_formats/supporting_your_own_format/) \- For supporting your own serialization and deserialization formats.

[Maintaining backwards compatability](https://rfl.getml.com/backwards_compatability/) \- Instructions on how to ensure that your API is backwards-compatible with older versions.

[Benchmarks](https://rfl.getml.com/benchmarks/) \- Extensive benchmarks of popular libraries for serialization, deserialization.
